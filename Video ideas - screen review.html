PROPOSED BEHAVIOUR · REVIEW BEFORE BUILD

From a creator’s upload to your next idea.

1. Add a creator. Paste their @handle or channel link. The app confirms the channel before adding it to your watchlist.

2. Choose a window. Show every public video published in the last 7, 14 or 30 rolling days, newest first. All three windows end now.

3. Review the topic. Keep the original headline and thumbnail, the creator, publication date and a link to YouTube. Search across the headlines.

4. Keep an idea. Save a source video for later. The preview selection lasts only while this page stays open; the finished tracker will save it to your account.

5. Refresh honestly. Show the last successful refresh. A failed creator refresh keeps the last data and marks it as out of date. Never show “No videos” for an API failure.

6. Protect access. Public creator tracking needs a server-side API key. Optional subscription import uses read-only Google consent. Your browser login is not an app API connection.

Build decisions and API evidence
  1. D-01: Header option three is already approved by Taylor in this chat. The screen below it is proposed for review.
  2. D-02: Recommend YouTube Data API v3, using channels.list, playlistItems.list and videos.list. Store channel and video IDs; deduplicate by video ID. Paginate the uploads playlist. Filter by the video publication timestamp, not when a playlist item was added.
  3. D-03: Default to 30 days and newest first. Display original YouTube titles and remotely served thumbnail URLs. Keep unavailable/deleted video handling and data refresh in the server layer.
  4. D-04: Add creators by handle. Subscription import is optional and requires Google OAuth with youtube.readonly. Creator selection is awaiting Taylor’s list.
  5. D-05: Refresh on demand and when opening stale data. Background refresh cadence will be agreed before scheduling. WebSub can supplement the initial backfill for new uploads and title updates.
  6. D-06: Move the existing site to a server-capable build while retaining all presentation files and routes. Store the watchlist and saved source IDs in durable storage. Keep the API key in runtime secrets. No new Google Cloud project, credential or account permission has been created.
  7. D-07: Sample age filters use the approximate age labels observed on YouTube for this preview only. Production filtering must use exact API timestamps.
